## Adapter notes / new-scraper plan

**NEW `src/adapters/html-scraper/city-of-exeter.ts` → `CityOfExeterAdapter` (HTML_SCRAPER).** This is a
title-parse recap-blog scraper; the closest working reference is **`src/adapters/html-scraper/ofh3.ts`**
(also a Blogspot recap blog using the Blogger API, hardcoded `startTime: "11:00"`, `kennelTags`
hardcoded). Mirror its structure: Blogger API primary (`fetchBloggerPosts(baseUrl)`), HTML-scrape
fallback (`.post-outer/.post`), `applyDateWindow(result, options?.days ?? source.scrapeDays ?? 365)`.

**The difference vs OFH3:** City of Exeter encodes everything in the **title**, not labeled body fields.
Parse the title, not the body:

```
"#1279 Chudleigh Knighton play park - NoButt and Mouthful - 11 October 2026"
   │     └─ venue ──────────────────┘   └─ hares ───────────┘   └─ date (year-bearing) ┘
   └─ runNumber (#NNNN)
```

Parsing plan (extract helpers so Sonar S3776 cognitive complexity ≤ 15):
- `extractHashRunNumber(title)` → runNumber (title always starts `#NNNN`).
- Strip the `#NNNN` prefix, then **split the remainder on `" - "`** into segments. The **date is ALWAYS the last segment** and **year-bearing** — parse with `chronoParseDate(lastSegment)` (handles full + abbreviated months "October"/"Oct"/"September"/"Sept"/"August", and the ordinal/separator drift the platform note lists). **Do NOT enumerate month names in a regex** (Sonar S5843) — let chrono validate. **Detect a run post by a parseable trailing year-bearing date; skip any post without one** (that filters the pre-run-number prose/PII posts).
- 🔴 **DO NOT assign `location`/`hares` by segment position.** The platform note (`source-platform-notes.md` → "City of Exeter H3 addenda") documents that the two middle dash-segments are **ORDER-INCONSISTENT across the archive** — recent posts are overwhelmingly `location - hare`, but older ones invert (2023 `#1091 Wide - Dawlish` = *hare - location*; "Wide" is a hash-name, "Dawlish" a town). Position alone cannot tell venue from hare, and a hare nickname dropped onto a map pin is silent corruption. **Default: leave both `location` and `hares` undefined** — `runNumber` + the trailing date are the only reliable title fields (same stance as the platform note). If you want to populate them for the recent era, gate it behind an explicit, tested heuristic (e.g. venue-keyword / known-hare-name lists) rather than raw position, and keep it conservative.
- **Title:** leave `title` **undefined** for all normal runs → merge synthesizes `"City of Exeter H3 Trail #N"`. Only set `title` for a clearly-thematic special (2-segment `<theme> - <date>`, e.g. #1273 "Spockfest hangover hash", or a themed first segment like #1274 "25th Anniversary Hash"). **Never set `title = hares`** (merge.ts title-fallback rule).
- `startTime: "11:00"` (hardcoded — Sunday 11am; not in the feed).
- `locationUrl`: when a venue is present, `https://www.google.com/maps/search/?api=1&query=${encodeURIComponent(venue)}` (OFH3 pattern); none otherwise.
