**Adapter flags** (`src/adapters/html-scraper/tribe-events-adapter.ts`, `toRawEvent`). Illustrative only:
```ts
// runNumberPattern?: string — regex with one capture group, tested before the #NNN path.
// titleVenueSegment?: boolean — titles shaped "Run NNNN – <segment>".
//   segment is TBC                         -> title undefined; location from venue if any
//   venue present, segment has UK postcode -> location = venue; title undefined
//   venue present, no postcode             -> keep segment as title (theme, e.g. #2166)
//   no venue                               -> location = segment; title undefined
```
Walked through the 12 live titles by hand: the rules work except #2155 and #2156 (past runs with a venue and no postcode), which would keep a pub name as the title. Those two only matter if the flag also runs on the backfill; if so, also treat the segment as a venue when it shares a word with the venue name or city. The dash varies: `&#8211;` and a literal `–` both occur, and the ICS uses `-`; `fetchTribeEvents` decodes entities first. Keep the regexes safe (no nested quantifiers; compile the config regex via the existing safe pattern, and expect Codacy's non-literal-`RegExp` flag).

**Description noise.** `stripHtmlTags` leaves `@`, blank lines and a repeated organizer line, e.g. `@\n\n\n\nOn On is at 6:45pm – ish\n\n\n\nTimekeeper & Ram`. Normalize in the same flag (drop the leading `@`, the organizer echo, collapse whitespace), or leave `description` undefined when nothing remains. Useful content does appear here (`On On at 6:45pm`, the Christmas party note), so don't discard it wholesale.
