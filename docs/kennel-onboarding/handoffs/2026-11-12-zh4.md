## Adapter notes

### 1. `parseDate` dot-separator support (`src/adapters/google-sheets/adapter.ts`)
Today `parseDate` splits on `/[/\-]/`, so `2.1.2026` gives 1 part → `null`, and **every Zagreb row is
dropped**. Minimal additive change:
- Strip one trailing `.` (`11.10.2025.` → `11.10.2025`).
- Split on `/[/.\-]/` so `D.M.YYYY` goes through the existing `dayFirst` branch.
- Check that nothing earlier in `parseDate` (`parseDMonDate`, `parseMonDDate`, the day-name parsers,
  `parseWeekdayPrefixedTriple`, which already accepts `.`) changes behaviour for existing sources.
  Run the full google-sheets test suite.
- Tests: `2.1.2026` + `dayFirst` → `2026-01-02`; `11.10.2025.` → `2025-10-11`; `19.12.2026` →
  `2026-12-19`; a dot date **without** `dayFirst` keeps the existing month-first behaviour (or is
  rejected — document whichever you choose).
- Optional: also accept the 2017-style two-digit year `11.11.17` (falls out of `normalizeYear` once
  `.` splits). Only the backfill needs it; the live window is 2025+.

newest-first: `2026`, `2025`, … `2011`. The fetch loop stops at the first tab with no events in the
window. With `scrapeDays: 365` it reads `2026`, `2025` and stops at `2024`. Non-year tabs (`Sheet2`,
`List 6`, …) are ignored.
