## How each branch was classified

1. **Ancestor:** `git rev-list origin/main..<branch>` is empty, so every commit is already in main (merge-committed PRs).
2. **Contained:** `git merge-tree --write-tree origin/main <branch>` yields main's exact tree, so merging the branch would change nothing (typical of squash-merged PRs).
3. **Squash-merged, later edited:** the branch tip equals the head of a **merged** PR (`refs/pull/N/head`), but main has since changed the same lines, so a re-merge would conflict.
4. Otherwise the branch carries changes not in main: either a **closed-unmerged** PR, an **open** PR, or **no PR at all** (possible lost work).

PR state comes from GitHub search (1,062 merged, 6 closed-unmerged, 7 open). Branch→PR matching is by exact tip SHA, so a branch that got commits *after* its PR merged shows as "no PR".
