# The agent root

Every HashTracks scheduled task starts in `~/Developer/hashtracks-agents/`, the agent root, and acts
on GitHub as the **HashTracks Agent** App, never as the owner ([`docs/ops/system.md#identity`](../../docs/ops/system.md#identity)).

The root is **not** a git repository, so no task's `git checkout -f` or `git clean -fdx` can touch it.
Project settings load from the folder a session *starts* in, so its `.claude/settings.local.json`
applies to the whole run, wherever the run later `cd`s.

| Path in the root | What it is |
|---|---|
| `bin/gh` → `bin/agent-gh.sh` | The `gh` shim, first on `PATH`. It mints a fresh App token on every call and runs the real `gh` with it; if minting fails it exits 97 and runs nothing. It answers `gh api user` with the bot's login that `install.sh` read from GitHub (the identity preflight), once a mint has succeeded, and `gh auth git-credential get` with the token (git's credential helper). |
| `bin/mint-token.sh` | Mints the installation token (bash, openssl, curl, jq). `--login` prints the bot login GitHub reports for the App's key. |
| `bin/check-root.sh` | The digest's drift check: the repo's deny rules are all denied here, the env block still isolates `gh`, and each task clone still pushes over HTTPS through the shim alone. Prints `root-settings: OK` or `root-settings: DRIFT: …`. |
| `.agent/config`, `.agent/app.pem` | The App id, installation id, key path, real `gh` path and bot login; the App's private key (mode 600). |
| `.agent/gh-empty/` | `GH_CONFIG_DIR`: an empty `gh` config, so `gh` has no stored login. |
| `.claude/settings.local.json` | Generated by `install.sh`: the env block below, the repo's `.claude/settings.json` permissions, and [`settings.extra.json`](settings.extra.json). |

The env block every Bash call of a session started in the root gets:

| Variable | Value | Why |
|---|---|---|
| `GH_CONFIG_DIR` | `<root>/.agent/gh-empty` | The real `gh` finds no stored login |
| `GITHUB_TOKEN`, `GH_TOKEN` | empty | No inherited token; the shim sets `GH_TOKEN` per call |
| `GH_REPO` | `johnrclem/hashtracks-web` | `gh` can't infer the repository outside a clone |
| `PATH` | `<root>/bin:` then the install-time `PATH` | The shim wins over the real `gh` |

Claude Code starts each session's shell from a snapshot of your shell, and the snapshot sets `PATH`
itself, so the `PATH` above never takes effect (the other variables do). `install.sh` therefore also
puts a small dispatcher at `~/.local/bin/gh`, which the snapshot's `PATH` reaches before Homebrew. It
runs the root's shim when `GH_CONFIG_DIR` is an agent root's empty config, refuses if that shim is
missing, and otherwise runs the real `gh` unchanged, so your own `gh` behaves as before.
`check-root.sh` rebuilds a task's shell from the latest snapshot and checks `gh` answers as the bot.

`settings.extra.json` adds the allow rules the tasks need and, as a speed bump rather than a control,
denies commands that set `GH_CONFIG_DIR`, `GITHUB_TOKEN` or `GH_TOKEN`, call `gh` by absolute path,
log `gh` in or print its token, or touch `.agent/`; `install.sh` also denies the file tools reading or
editing `<root>/.agent/**`. The key stays readable by the owner's OS user whatever the rules say: these
rules are speed bumps against mistakes, not a boundary.

## Install (owner)

1. Create the HashTracks Agent App and install it on the repository
   ([`infra/github-apps/README.md`](../github-apps/README.md)), saving its key with
   `create-app.sh convert <code> ~/hashtracks-agent-app.pem`.
2. From a checkout of `main`:

   ```bash
   bash infra/agent-root/install.sh --app-id <app id> --installation-id <installation id> --key ~/hashtracks-agent-app.pem
   ```

   It copies the key into the root (then delete `~/hashtracks-agent-app.pem`), proves it can mint a token, writes
   the settings, and points each task clone (`hashtracks-audit-fixer`, `hashtracks-implementer`,
   `hashtracks-research` under `~/Developer`) at the bot: an HTTPS remote, the shim as git's only
   credential helper, and the bot as commit author. It ends with `root-settings: OK`.
3. In the Claude desktop app, change each of the six scheduled tasks' folder to
   `~/Developer/hashtracks-agents`. If a task's folder can't be changed, recreate the task from a
   session started in the root, with the same pointer prompt, schedule and mode, then check its
   `originCwd` is the root.
4. Leave the identity preflight at `LOG` until each task has logged the bot's login on a real
   scheduled run ([`system.md#identity`](../../docs/ops/system.md#identity) has the four-step order).

Re-run `install.sh` after any change to this folder or to the repo's `.claude/settings.json`; the
digest reports `DRIFT` until you do.
